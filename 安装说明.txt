Salient 凸显 · 本地服务安装说明
版本 r12

一、装之前需要什么
  1) Node.js 22 或更高版本（https://nodejs.org/ ，一路下一步即可）。
  2) 一个浏览器（Chrome / Edge 都行）。发布功能要用它登录一次自媒体账号。
  3) 能上外网。
  4) 一个模型 Key（写稿要用）。SiliconFlow 或 DeepSeek 任选一个，
     申请地址在下面第五节；没有也可以先用「演示模式」把流程看一遍。

二、怎么装（一步）
  双击「安装.cmd」。它会自己做四件事：
    1) 装发布依赖（约 14 MB，只装驱动，不下载浏览器）
    2) 环境自检（缺什么会说清楚）
    3) 设置开机自动启动
    4) 启动服务并自动打开首页
  看到「装好了」就可以了。第一次进入会让你设一个访问口令 —— 那是你自己的空间钥匙。

  装好之后：
    开机自动启动，不用再双击任何文件；浏览器打开 http://127.0.0.1:8810/ 即可。
    想手动启动一次：双击「启动.cmd」（关掉那个窗口不影响服务）。
    要停止服务：双击「停止.cmd」。
    不想要开机自启：双击「取消开机自启.cmd」（不删数据）。

  macOS / Linux：执行 sh 安装.sh，其余行为相同。

  团队一起用（可选，只适合内网）：
    双击「开放局域网访问.cmd」。它会把服务改为对内网开放，并打印同事该敲的地址。
    其他电脑什么都不用装，用浏览器打开那个地址就行。
    ★ 同事该敲哪个地址：双击「查看当前地址.cmd」随时能看，给两行 ——
      第一行是计算机名（http://<计算机名>:8810），IP 变了也不影响，优先用这行；
      第二行是当前内网 IP（http://192.168.x.x:8810），主机名解析不了时用它。
      这台机器若是自动获取 IP（DHCP，多数办公机都是），IP 过几天可能就变了，
      地址打不开不代表系统坏了 —— 再点一次「查看当前地址.cmd」拿新地址即可。
      想彻底不用管这件事：请 IT 在路由器上给这个 MAC 地址做一条"DHCP 保留"（固定分配）。
    ★ 第一次多半连不上，是 Windows 防火墙挡了入站。用【管理员】命令行执行一次：
      netsh advfirewall firewall add rule name="Salient Studio" dir=in action=allow protocol=TCP localport=8810
    ★ 数据只在这一台机器上，别的电脑是"连过来用"，不是"各自存一份"。
    ★ 不要把这个端口映射到公网；要让外部客户看，请用客户门户的只读口令。
    ★ 不要把 data 目录放到网盘或共享文件夹里 —— 数据库文件在网络盘上会写坏。
    ★ 发布是在这台机器上执行的：同事在别的电脑点「发布」，浏览器窗口会在**这台机器**
      的屏幕上弹出来（扫码要它扫）。同一时间只让一个人发，别两个人抢同一个窗口。
    ★ 这台机器要一直开着、且保持有人登录状态：注销或关机后同事就连不上了。

三、不需要什么（重要）
  · 不需要安装 WorkBuddy 或其他宿主软件。
  · 不需要宿主软件授权，也不借用宿主运行时。登录自媒体账号时，系统会自己开一个干净的浏览器窗口让你扫码，
    扫码后的凭证存在本目录下的 data/ 里，不会读取你电脑上已有的浏览器数据。
  · 不需要管理员权限（装在当前用户目录即可）。
  · 不需要数据库。数据是本目录下的 sqlite 文件，拷走这个目录就是完整备份。

四、数据在哪
  data/tenants/<空间名>/studio.db   每个空间一个独立文件，互相看不到。
  data/tenants/<空间名>/articles/   稿件素材。
  .env                              配置（模型 Key、图床、邮箱）。本包自带一份空白模板，填法见第五节。

五、模型 Key 填在哪（第一次用必看）
  本目录下有一个名为 .env 的文件（就是这个文件，没有扩展名）。用记事本打开它，
  找到这一行：
      SILICONFLOW_API_KEY=
  在等号右边贴上你的 Key，保存，然后双击「停止.cmd」再双击「启动.cmd」即可。
  申请：打开 https://cloud.siliconflow.cn/ → 注册登录 → 「API 密钥」→ 新建。

  · 也可以不碰文件：打开工作台 → 设置 → 后台 .env，在界面里填同一份配置。
    两处改的是同一个文件，改哪边都行，不要两边各填一半。
  · 只有一个 Key 也能跑：填 SILICONFLOW_API_KEY 就够。DEEPSEEK_API_KEY 是
    主通道失败时的兜底，留空不影响使用。
  · 只有 Key 没有余额，报错会写「额度 / 401」，那不是装错了，是账户需要充值。
  · 这个文件里有 Key，等同于你的账号：不要发到群里、不要传网盘、
    不要把整个目录打包给别人。要给同事用，让他连你的地址（见第二节「团队一起用」）。
  · 环境自检（node scripts/doctor.js）里有一行「模型 Key」：
    显示 [--] = 还没填，服务照常启动、看板与稿件都在，只有生成会失败。
    填好并重启后这一行会变成 [OK]。

六、出问题先看这里
  · 双击「安装.cmd」一闪而过、或提示"无法运行 / 已阻止"：
    这个包是从网上传过来的，Windows 会给它打上"来自网络"的标记，脚本就被挡住。
    解决：右键那个 zip 文件 → 属性 → 勾上"解除锁定"→ 确定，然后重新解压一遍。
  · 双击后窗口闪一下就没了、也没装好：用【管理员】命令行在解压目录里执行 安装.cmd，
    这样错误信息会停在窗口里，方便截图发给我们。
  在目录里执行：node scripts/doctor.js
  它会把 Node 版本、依赖来源、目录权限、端口占用逐条打出来。
  其中任何一项写着「宿主」就说明还在借用外部运行环境，把这行发给我们就行。

七、发布依赖（必读）
  本包不含第三方 node 包（保持零依赖：包小、可直接拷贝、升级也简单）。
  渠道发布需要 playwright-core，双击「安装依赖.cmd」一次装好即可（约 14 MB，只装驱动不装浏览器）。
  ★ 这不是"可选增强"：渠道发布、登录态续期、PDF 导出都靠它。不装则发布按钮全部不可用。
  浏览器用机器上已有的 Chrome 或 Edge 即可，不需要另外下载浏览器。
  另需本机 Python 3.9+（脚本只用标准库，不需要 pip install）。
  客户机完全不能上网时：在能上网的机器上装好，把 node_modules 整个目录拷到本目录即可。

八、登录态会不会自己续（"还要不要有人扫码"）
  · 会自己续。后台每 6 小时自查一次，并在凭证到期前 12 小时自动续期：
    带着现有凭证访问一次平台后台，平台下发新凭证，立即存回该空间自己的登录态目录。全程无窗口、不用人。
  · 不要为了"省事"把自查周期改长（--keeper-every=24h 这种）。到期前多久开始续，
    是跟着周期自动算的（周期×1.5），所以改了不会漏；但周期越长、窗口越宽，
    续期触发得越早、开浏览器反而越频繁 —— 6 小时是最省的，不是最保守的。
  · 但"能续"不等于"永远不用扫码"。下面三种情况必须有人在这台电脑上操作一次：
      1) 凭证已经彻底过期 —— 比如这台机器连关三天，错过了续期窗口；
      2) 平台主动作废 —— 改了密码、在别处退出登录、触发风控；
      3) 公众号这类"登录态存在浏览器目录里"的渠道，目录被删或换了电脑。
  · 六个渠道没有一家支持"无人值守重新登录"（公众号要手机扫码，头条/百家号是密码+风控），
    所以续期做得到，"重新登录"做不到 —— 这是平台限制，不是本系统省事。
  · 想看现在的状况：双击「检查登录态.cmd」。它只读不改，会列出每个渠道剩多久、要不要人。
  · 出现「需人工」时先看类型，两种处理办法相反：
      「网络」= 这台机器连不上平台（LinkedIn 常见，需要境外出口）—— 换凭证没用，先修网络；
      「登录失效」= 真的过期了 —— 打开工作台 → 渠道账号 → 对应渠道 → 「更新 Cookie」，扫一次码。
  · 一句话：正常使用下几个月都不必扫码；机器长时间关机、或平台改了安全策略时才需要人。
  · 这台机器是团队共用的话，扫码这件事只能在这台机器上做（浏览器窗口开在它的屏幕上）。

九、登录态存在哪（每个空间一份）
  · 每个空间（default 也算一个普通空间）有且只有一处登录态：
      data\tenants\<空间名>\auth\
    公众号这类"登录在浏览器里"的渠道，是这个目录下的一个子目录（wechat_profile）。
  · 这里没有"系统共用登录态"。别的空间登过，不代表这个空间登过；
    没登录就是没登录，系统会直说「该空间还没有这个渠道的登录态」，
    不会悄悄拿别人的号把稿子发出去。
  · 为什么改成这样（真事）：以前有一套系统级登录态兜底。客户空间忘了登录时，
    系统会拿它把稿发出去 —— 界面上一切正常，只有平台后台的发表记录能看出署名不对。
    迁移时更糟：只拷 data\ 给别人，那套系统级登录态还在你这台机器上，
    你以为交的是空系统，实际两边都在用同一个号。
  · 换机器：只搬 data\ 不够。登录态目录里的 profile 是 Windows 加密的（DPAPI，
    按"本机 + 本 Windows 账户"加密），拷到别的机器、或换个 Windows 账户登录，
    浏览器打开就是未登录态 —— 而现象看起来像网络问题，很难查。
    想把登录态带走，用仓库里的快照工具（在 studio 目录下）：
      已经登录好的机器：  node scripts\vault.js export
      新机器：            node scripts\vault.js restore
    快照是明文 cookie（约 60KB），公众号/搜狐会在新机器上重建 profile，不用重新扫码。
    ★ 快照等同身份凭证：只放私有仓库，绝不拷进客户机器、绝不随安装包发出去。
    scripts\_legacy_* 是旧版本留下的只读备份，不参与发布，确认新环境正常后可以删。
